# 卡片规范

## 每张卡必须有的字段

| 字段 | 要求 |
|---|---|
| 序号水印 | `01` `02` `03`，超大字号半透明，压在卡片右上或背景 |
| 仓库名 | 用 `owner/repo` 全名，链接指向 `https://github.com/{full}` |
| 硬指标 | Stars / 语言 / 协议 / 最近提交日期，全部来自 `repo_meta.py` 的实测输出 |
| 定位标签 | 一行 2–4 个词，如 `视频 / 本地 / 免费` |
| 它干什么 | 两三句人话，不用术语堆砌，不用「赋能」「一站式」这类词 |
| 为什么给你 | 结合画像里的具体处境写，这是整张卡的核心 |
| 上手成本 | 写明是否需要编译、是否有 GUI、是否需要 Python 环境、下载体积量级 |
| 机器可行性 | 结合硬件写：显存够不够、C 盘放不放得下、Win10 能不能跑、A 卡兼容性 |
| 坑 | 2–3 条实话，包括已知 bug、维护状态、学习曲线、隐性成本 |
| 结论 | 一句话：值得装 / 观望 / 别碰 |

## 文风

- 克制、直给、不吹。像跟朋友说话，不像写评测
- 判断句优先于描述句。「这东西对你有用」而不是「这是一个优秀的工具」
- 允许说缺点，允许说「这个我不推荐你装」
- 不写「感兴趣可以看看」「希望对你有帮助」这类废话

## 反例（出现即重写）

- 「这是一个功能强大的开源项目，支持多种格式，社区活跃」——全是废话，没有信息
- 「结合你的需求，这款软件非常适合你」——没说是哪个需求，也没说不适合的地方
- 「Stars 高达 5k，非常流行」——流行不等于对这个人有用
- 把 README 的功能列表原样翻译成中文当作介绍

## 「为什么给你」的写法

对照画像逐条检查，至少命中一条具体的：

- 他的机器跑不跑得动（显存 / 磁盘 / 系统版本 / A 卡）
- 能不能省钱或省时间，省多少要能感知
- 能不能变成收入，路径要具体
- 是否踩了他明确讨厌的东西（付费墙、养号、排队抽卡）

命中不了任何一条，这个项目就不该出现在卡片里。

## 视觉

沿用 `assets/card-template.html`：浅色纸感背景 `#faf9f7`，白色卡片 + 1px 细边框 + 极轻投影，砖红强调色 `#b8442a`，序号大字水印。不加大面积渐变，不用霓虹色，不做花哨动效。
