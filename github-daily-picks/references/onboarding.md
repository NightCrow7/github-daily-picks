# 首次上手：从历史对话里把这个人读出来

目标：在第一次运行时，用 agent 已有的对话记录生成一份可用的 `profile.md`，取代让用户手填问卷。用户不需要知道自己被问了什么，只需要在最后确认一次。

## 为什么这么做

问卷拿到的是「用户以为的自己」——他填「我需要效率工具」，实际他真正的问题是 C 盘只有 99GB。历史对话拿到的是「实际发生过的事」：他抱怨过什么、买过什么、放弃过什么、为了什么纠结了半小时。后者才是有用的筛选依据。

## 第一步：检索

按维度逐个检索，每个维度至少换 2–3 组关键词重试，中英文都试。

| 维度 | 检索关键词示例 |
|---|---|
| 职业与收入 | 「剪辑」「接单」「闲鱼」「稿费」「单价」「收入」「客户」 |
| 收入模式偏好 | 「被动收入」「躺赚」「不想上班」「副业」「低成本」 |
| 硬件配置 | 「显卡」「CPU」「内存」「主板」「电源」「装机」「配置单」 |
| 硬件问题 | 「黑屏」「蓝屏」「卡」「温度」「掉帧」「容量不够」 |
| 常用软件 | 「剪映」「PR」「达芬奇」「下载」「网盘」「浏览器」 |
| 审美偏好 | 「好看」「风格」「配色」「壁纸」「调色」「电影」 |
| 明确讨厌 | 「烦」「讨厌」「不想」「受不了」「太麻烦」 |
| 踩过的坑 | 「失败了」「放弃了」「不好用」「退款」「卸载」 |

检索工具按环境选择：

- **WorkBuddy**：`conversation_search`（跨会话检索）；本地记忆文件 `~/.workbuddy/user-*/MEMORY.md` 与工作区 `.workbuddy/memory/YYYY-MM-DD.md`
- **Claude Code**：`~/.claude/projects/*.jsonl` 会话记录，用 grep 检索
- **Codex CLI**：`~/.codex/sessions/`
- **无历史可读的 agent**：跳过检索，直接进第三步的问卷模式

## 第二步：抽取

对每条结论标明来源，这是质量的关键：

- `（用户原话）`——他自己说过的，可信
- `（推断）`——从行为反推的，比如「他反复问千元内显卡，推断预算敏感」
- `（冲突）`——不同时间说法不一致，取最近一次，并注明时间

必须抽取的六块，缺一块就补搜：

1. 身份与收入（职业、收入量级、价格敏感度）
2. 硬件环境（型号要具体，A 卡还是 N 卡必须明确）
3. 工具栈（在用什么、放弃了什么）
4. 审美与偏好（在意什么、明确不在意什么）
5. **明确回避**（这一项价值最高：讨厌的工作方式、不接受的付费模式、不能碰的领域）
6. 忌口（时间精力限制、网速、是否接受命令行、家人共用设备等）

矛盾信息处理原则：以最近的为准；行为证据优先于口头表态（他说「我不在乎价格」但每次都问最便宜的，以行为为准）。

## 第三步：给本人过目

把画像压缩到 400 字以内发出来，结构固定：

```
我翻了下我们之前的聊天，把你读成这样（有错直接改）：
· 你是谁：…
· 你的机器：…
· 你在意 / 不在意：…
· 你明确不想要的：…
这几条是从你原话来的，稳定；下面两条是我推的，可能不准：…
```

三条硬规则：

- 推断项必须显式标出来，不能让用户以为全是他自己说的
- **不要写**身份证、住址、真实姓名、具体薪资数字、账号密码。收入写成量级（「月入一两千」），不写精确数
- 用户说「别分析我」就立刻停，退回问卷模式，并且不落盘

## 第四步：落盘

写入技能目录的 `profile.md`，结构对齐 `references/profile-template.md`。在文件末尾加一段：

```
## 画像来源
- 生成方式：历史对话抽取（YYYY-MM-DD）
- 待补：…
```

## 之后：持续修正

每次运行推荐前，如果当天对话里出现了新的硬事实（换了显卡、接了新类型的单、明确说了讨厌什么），追加进 `profile.md`，标注日期。不要每次重写整份，只追加和改冲突项。

## 失败模式

- **检索不到任何个人信息**：不要硬编。直接说「我这边没有你的历史记录」，发问卷
- **只搜到零星几条**：生成的画像标注「信息不足」，第一次推荐时把判断放保守，并在摘要里说明「画像还浅，推错请骂我」
- **用户历史里有敏感内容**：跳过不写，不要在画像里复述
