# GitHub daily picks

给一个具体的人做「每日三个开源项目」推荐，而不是给所有人做热门榜单。核心差别在于：**所有筛选和评语都锚定这个人的真实处境**——他的硬件、预算、收入模式、审美偏好，以及明确讨厌的东西。

## 产出

- 一张 HTML 详情卡片（浅色纸感背景 + 白卡 + 序号水印），三个项目各占一卡
- 一份去重记录（已推荐仓库清单），保证不重复推
- 一段 200 字以内摘要，每条直接给判断：值得装 / 观望 / 别碰

## 首次使用：把这个人读出来，而不是让他填表

**这是本技能最重要的设计**：第一次运行时，不要让用户填问卷，而是让 agent 主动遍历他们之间已有的对话记录，从真实聊天里把这个人读出来，写成 `profile.md`，然后才推项目。详细流程见 `references/onboarding.md`，要点：

1. **翻历史**。用当前环境具备的对话检索能力（WorkBuddy: `conversation_search`；其他 agent 用它自己的会话历史/记忆文件）按维度搜索：职业与收入、硬件配置、常用软件、审美偏好、明确讨厌的东西、踩过的坑。每个维度至少跑一次检索，搜不到再换关键词。
2. **抽取并标注来源**。每条画像结论后面标 `（用户原话）` 或 `（推断）`。推断占多数的字段，后面给的项目判断要保守。
3. **给本人过目**。把画像摘要（不超过 400 字）发给用户看，明确说「有错的直接改」，等他确认或修正后再落盘。
4. **落盘**。写入技能目录的 `profile.md`，格式对齐 `references/profile-template.md`。
5. 历史记录太少（少于 5 段有效对话，或检索不到任何个人信息）时，才退回问卷：把 `references/profile-template.md` 发给用户填。

禁止跳过这一步直接按热门榜单推荐。也禁止把推断当事实写进画像而不标注。

## 前置：profile.md（已存在时）

读取技能目录下的 `profile.md`，这是筛选的唯一依据。字段包括：

- 身份与收入模式（职业、收入量级、是否价格敏感）
- 硬件环境（CPU / GPU / 内存 / 系统版本 / 磁盘余量，A 卡还是 N 卡要写清）
- 已用工具栈（常用软件、AI 工具）
- 审美与内容偏好（在意什么、不在意什么）
- 明确讨厌或回避的东西（权重最高，直接决定否决）
- 忌口（付费墙、涉灰产、需要长期养号等）

画像里写明的「回避项」是硬否决：命中即淘汰，不做权衡。

## 工作流

1. **读上下文**。读 `profile.md` 与 `<工作目录>/github-daily/已推荐记录.md`（不存在则新建）。已推过的仓库本次不得重复。
2. **扫候选**。用 `scripts/search_repos.py` 按下面四条线各扫一遍，每条取 2–3 个进候选池：
   - 主业工具：与画像中职业直接相关的生产力工具（剪辑、素材、字幕、转码、人声分离、超分补帧）
   - 变现与轻资产：能低成本自建、跑起来后维护成本低的小工具或自托管服务
   - 省钱与提效：比价监控、硬件检测、磁盘瘦身、下载工具、系统提效
   - 兴趣向：与画像中娱乐偏好直接相关的项目
   ```bash
   python scripts/search_repos.py --query "video subtitle remover" --query "video super resolution" --min-stars 300 --months 12
   ```
3. **过硬门槛**。逐条判定，任一不满足即淘汰（见下节）。
4. **核准数字**。对入围的 3 个仓库逐个查真实元数据，**禁止凭记忆写 stars**：
   ```bash
   python scripts/repo_meta.py owner/repo other/repo
   ```
5. **写卡片**。复制 `assets/card-template.html` 为 `<工作目录>/github-daily/卡片-YYYY-MM-DD.html`，按 `references/card-spec.md` 填三个卡片块，日期用运行当天。
6. **更新记录**。在 `已推荐记录.md` 表格末尾追加当天三行（日期 / 仓库 / 一句话定位）。
7. **回复**。给 200 字以内摘要，点明三个项目各解决什么痛点，再用 present_files 推出当天卡片。

## 硬门槛

- 开源且可本地运行（有 release 或能自行构建）
- 免费或极低成本；**不接受「必须买会员 / 必须充值付费 API 才能用」**
- 近 12 个月内有提交（`pushed_at` 落在窗口内）
- stars ≥ 300（低于此说明社区验证不足，不推）
- 非 fork、非 archived
- 明确回避：长期养号、批量登录态爬取、刷单挂机、灰色产业链

## 卡片要求

字段、文风、反例见 `references/card-spec.md`。三条不可省：

- 评语必须落到画像里的具体处境，不能写成通用介绍
- 必须写清在他自己的机器上能不能跑（涉及显存、C 盘余量、系统版本时明说）
- 必须写 2–3 条实话实说的坑

## 边界

- 数字只来自 API 实时查询，宁可少写也不要编
- 当天找不到 3 个真正合格的，只推 1–2 个，并在摘要里直说「今天池子里没好东西」，不凑数
- 禁止「感兴趣可以看看」这类废话，每条都要给明确判断
- API 限流：未登录搜索接口 10 次/分钟、核心接口 60 次/小时；批量查询前设置 `GITHUB_TOKEN` 可提升到 5000 次/小时

## 反模式

- 推「又一个 AI 聊天客户端」这类与画像无关的热门项目
- 把 README 的营销话术翻译一遍当评语
- 为凑满三个，把不达标的项目降级塞进去
- 只写优点，不写坑
